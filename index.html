Pipe Network: Flow Simulator

A generic pipe-network builder with a refinery case at its heart: multiple pipes at different elevations, coming together. Load a use case, edit the tables, add your own pipes, and the whole network settles at once.

This is an AI project exploring AI capabilities. It was planned and built with AI models under student direction, for a fluid mechanics course. The full process, the models used, and the decisions taken are documented on this page. As our professor put it when he set this direction, network flow analysis of this kind needed dedicated software costing over $10,000 only a few years ago; the story of building it from course notes with AI is the point of the project.

Symbols for this panel: Dt is the receiving tank inside diameter (m); At is its cross-section area (m²); hstart and hmax are liquid levels measured as heights above the tank bottom (m); Vol is the volume to add (m³); Qfill is the total flow the solved network delivers into the selected tank (m³/s); ttarget is a target fill time (min); Vtarget is a target mean velocity in the fill pipe (m/s). Every preset value in the examples is a stated demo preset [R7], not plant data. Fitting values come from the standard table [R4]; fluid properties and roughness from the standard tables [R5], except the two stated fluid presets. The theory behind every number is on the Theory and Math tab.

How the calculation works

Every pipe in the network obeys the same course equation. The network is solved by requiring that equation to hold in every pipe at the same time, with one shared head at each junction. The unknowns are exactly two sets: the head H at each junction, and the flow Q in each pipe. Everything reported is derived from those.

CLASS-W10/W11[R1]
Hstart − Hend + Hpump = hL
The engineering form of the Bernoulli equation, in head form, between the two ends of one pipe: the head given up between the ends, plus any head the pump adds, is exactly the head the pipe loses. Hpump is zero in every pipe without a pump.
CLASS-W11CLASS-HW4CLASS-W13[R1][R2][R4]
hL = ( 4 fF L/D + K ) · V|V| / (2g)
Head loss in a pipe: a friction term built from the Fanning friction factor fF, the length-to-diameter ratio L/D, plus the fittings term K, all multiplying the velocity head. The product V|V| keeps the loss pointing against the flow when a pipe runs backward.
CLASS-HW4CLASS-W11[R2][R3]
Laminar: fF = 16 / Re  Turbulent: fF from the Churchill correlation, with Darcy factor = 4 fF
The laminar result is derived in class from the Hagen-Poiseuille profile. The turbulent value uses the Churchill correlation, which covers all regimes and is stated in the Darcy form, so the page divides by 4 to work in the Fanning form the course uses.
CLASS-W11[R1][R5]
Re = ρ V D / μ  V = Q / A
The Reynolds number sets the regime: laminar below 2300, transitional from 2300 to 4000, turbulent above 4000, the standard textbook convention.
CLASS-W5/W6[R1]
At every junction: sum of Q flowing in = sum of Q flowing out
Continuity. This, plus one shared head per junction, is all that couples the pipes into a network.
CLASS-W5/W6[R1]
Vol = At (hmax − hstart) t = Vol / Qfill Qrequired = Vol / ttarget D = √( 4 Qrequired / (π Vtarget) )
Tank filling, the solve-for panel's arithmetic. At is the tank cross-section area, hmax and hstart are the max fill level and start level as heights above the tank bottom, Vol is the volume to add, Qfill is the flow the network delivers into the tank, ttarget is a target fill time, Vtarget is a target mean velocity, and π is the mathematical constant pi. The fill flow is constant because Example 6 discharges over the top of an open tank at a fixed elevation: the discharge point is the top of the tank, so the rising level never pushes back on the pipe. The last relation is continuity solved for a diameter, the same sizing idea as HW5 [R2].
CLASS-W11NEW-EXT speed scaling[R1][R7]
Hpump = s² H0 − kp Q|Q|  P = ρ g Q Hpump / η
The pump gives head that falls as flow rises, along a stated preset curve. Raising the speed ratio s raises the curve by the affinity scaling. Shaft power follows from the flow, the head gained, and the efficiency.
CLASS-W13[R1]
Leq = K D / (4 fF)
Equivalent length: the fittings on a pipe destroy the same head as this much extra straight pipe. The course notes are explicit that K itself is experimental, supplied by manufacturers and tables, which is why every K on this site carries a table citation.
Beyond the course — extension list. NEW-EXT These items were not taught as named methods in this course. They are built from the class pieces above, and the team is learning them as new material before presenting:
1. Solving all pipes at once by iteration (the node-head method): guess the junction heads, compute every pipe's flow, adjust the heads until flow balances at every junction. The reference implementation uses library root-finders [R6]; the page solver is cross-checked against it.
2. Pump speed scaling by the affinity relations, used by the pump speed inputs.

The code, block by block, with the reasoning

Block 1 — the friction factor

function fanningF(Re, D, eps) {
  if (Re <= 0) return 0;
  if (Re < 2300) return 16 / Re;
  const a = Math.pow(2.457 * Math.log(1 / (Math.pow(7 / Re, 0.9) + 0.27 * eps / D)), 16);
  const b = Math.pow(37530 / Re, 16);
  const fDarcy = 8 * Math.pow(Math.pow(8 / Re, 12) + 1 / Math.pow(a + b, 1.5), 1 / 12);
  return fDarcy / 4;
}

Reasoning. The course works in the Fanning form, so the whole tool does too, and the one conversion lives in exactly one place: the Churchill correlation [R3] is published in the Darcy form, so its result is divided by 4 on the last line, because the Darcy factor is 4 times the Fanning factor CLASS-W11. Below a Reynolds number of 2300 the code returns the laminar result 16 / Re, which is not a correlation: it is derived in class from the Hagen–Poiseuille profile CLASS-HW4. Using Churchill for the turbulent side means one formula covers the transitional band as well, so the solver never jumps between correlations mid-iteration.

Block 2 — one pipe: flow from its end heads

function pipeFlow(dH, p, rho, mu) {
  const A = Math.PI * p.D * p.D / 4;
  function resid(Q) {
    const V = Q / A;
    const Re = rho * Math.abs(V) * p.D / mu;
    const fF = fanningF(Math.max(Re, 1e-9), p.D, p.eps);
    const loss = (4 * fF * p.L / p.D + p.K) * V * Math.abs(V) / (2 * G);
    let gain = 0;
    if (p.pump) gain = p.pump.s * p.pump.s * p.pump.H0 - p.pump.kp * Q * Math.abs(Q);
    return dH + gain - loss;
  }
  // bisection on resid(Q) between -3 and 3 cubic metres per second
}

Reasoning. A pipe cannot be solved by a formula, because the friction factor depends on the flow that is being solved for. So the code defines one residual: end-head difference, plus pump gain, minus head loss, all as a function of the flow Q, and finds the Q that makes the residual zero. The loss is written with V times |V|, never V squared: the product carries the sign, so a pipe running backward loses head in the correct direction automatically. That sign is also this project's cautionary tale. The first feasibility version wrote the loss with the wrong sign treatment and most flows silently collapsed to zero; nothing looked broken until a laminar test case with a known answer exposed it. That test now runs before anything is published, and it is why the checker exists.

Block 3 — the network: balance at every junction

function balance(x) {          // x holds the current guess of junction heads
  const H = heads(x), r = new Array(free.length).fill(0);
  for (const p of pipes) {
    const q = pipeFlow(H[p.a] - H[p.b], p, rho, mu).Q;
    if (p.a in idx) r[idx[p.a]] -= q;   // flow leaving a junction
    if (p.b in idx) r[idx[p.b]] += q;   // flow arriving at a junction
  }
  return r;                      // zero at every junction = solved
}

Reasoning. The unknowns are the junction heads, nothing else. For any guess of those heads, every pipe's flow follows from Block 2, and the imbalance at each junction follows from continuity CLASS-W5/W6. A Newton iteration with a numerically built Jacobian, plus a line search that only accepts steps which shrink the worst imbalance, drives every imbalance below 1e-10 cubic metres per second. Solving all pipes at once this way is the one numerical method on the site that was not taught as a named method in class NEW-EXT; it is assembled entirely from class pieces. The Python reference core solves the same system with library root-finders instead [R6], so the two implementations share the physics and nothing else, which is what makes their agreement a real check.

Block 4 — why there are two implementations

Reasoning. AI-DECISION The Python core was written first, in the course's Fanning form, and frozen as the standard. The browser solver was then written to reproduce it, because the public site must load instantly with no large in-browser Python download on a school network. Before any version is shown, the Python known-answer tests run (a laminar pipe against Hagen–Poiseuille, the preset network's balance and flow ordering, a 10-pipe and 4-pump stress network, a deliberately reversed branch, a water check case, and a hand-solved laminar series network), and then the cross-check requires the browser solver to match the Python numbers on every example in the library. At the time of writing: 22 Python checks and 7 browser cross-checks, all passing.

Decisions made, and why

DecisionReason
Build a generic network tool first; the refinery network is Example 1, not the productAI-DECISION The professor's brief was a table of sources and sinks, not one fixed plant. A generic engine with a use-case library demonstrates the capability and teaches more per example.
Caps of 12 nodes, 10 pipes, 4 pumps, enforced with guardrailsThe group's agreed maximum size. The guardrails refuse what cannot be solved: a part of the network with no fixed-head node, a pipe from a node to itself, duplicate names, and non-positive diameters or lengths, each with the reason shown.
Work in the Fanning friction form everywhereIt is the course's form CLASS-W11; converting once, inside the friction block, prevents the classic Fanning-versus-Darcy factor-of-4 error everywhere else.
The roughly 2 m/s economic velocity is a design check, never a controlIt comes from the optimal-diameter analysis CLASS-HW5. The tool flags pipes far from it; it does not silently resize anything.
A correction on fittings: K measures loss, it does not keep flow laminarAn early group suggestion described fitting coefficients as a way to keep flow laminar. The Reynolds number sets the regime; K only prices the head a fitting destroys CLASS-W13. The site teaches it that way.
Every technical value carries a reference; preset values are labelled as presetsThis is an academic submission. Course material is cited by week and homework, external values to their paper or textbook table, and invented demo values are declared as stated presets [R7] rather than dressed up as data.
Dev labels visible in working builds, removed by one setting in the final buildThe team audits where every statement came from (class, homework, extension, or a logged AI decision) before presenting it as their own work.
Process evidence kept in a decision recordThe plan was generated by Muse; a second AI model is producing a parallel iteration for comparison, led by Drew Corbitt; every suggestion is logged with an accept or reject decision and a reason, and the site's process text is written from that record.
Final demo case: two source tanks fill one open receiving tank, over the top, to its max fill levelThe team's simplification decision. Discharging above the max fill level at a fixed elevation keeps the fill flow constant, so fill time is an exact continuity calculation; the lift is measured from the network to the top of the tank, and the tank's liquid level is volume bookkeeping only. The fill panel solves for the variable the user does not know: fill time, required flow for a target time (checked honestly against what the pump and network can deliver), or a diameter for a target velocity.
